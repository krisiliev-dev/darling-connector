Съдействие при проблем
======================

.. weight:: 40

При възникнал проблем или неочаквано поведение при работа с Barsy API, екипът ни може да извърши проверка — при условие че получим необходимата структурирана информация.

Моля, прочетете внимателно указанията по-долу **преди** да се свържете с нас.


Необходима информация
---------------------

За да можем да проследим и диагностицираме конкретна заявка, **задължително** ни изпратете следните данни:

1. **Хост** — адресът на сървъра, към който изпращате заявките (напр. *https://xyz.barsy.bg* или *https://abc.barsy.online* )
2. **Потребителско име** — акаунтът, с който се автентикирате
3. **BARSY_REQUEST_ID** — уникален идентификатор на заявката, върнат от сървъра
4. **Описание на проблема** — какво наблюдавате, какво очаквате и по какво се различават двете

   .. warning::

      **Никога не изпращайте пароли.** Нуждаем се единствено от потребителското име.

Как да намерите BARSY_REQUEST_ID
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Идентификаторът ``BARSY_REQUEST_ID`` се връща като HTTP Response Header в отговора на всяка заявка към Barsy API. Пример:

.. code-block:: http

   HTTP/1.1 200 OK
   Date: Fri, 20 Mar 2026 14:08:53 GMT
   Server: Apache/2.4.66 (Debian)
   BARSY_REQUEST_ID: 1:108914
   X-BarsyVersion: nf34sz34
   Expires: Thu, 19 Nov 1981 08:52:00 GMT
   Keep-Alive: timeout=5, max=99
   Connection: Keep-Alive
   Transfer-Encoding: chunked
   Content-Type: application/json ; charset=UTF-8

В този пример стойността е **1:108914**. Този идентификатор ни позволява незабавно да открием конкретната заявка в системните логове.

.. tip::

   Повечето HTTP `клиенти </barsy.help/210-dictionary/client.html>`__ (Postman, curl, Insomnia и др.) позволяват преглед на Response Headers. Ако разработвате собствена интеграция, препоръчваме да логвате стойността на ``BARSY_REQUEST_ID`` за всяка заявка — това значително ускорява диагностиката при проблем.


Алтернативен вариант (без BARSY_REQUEST_ID)
-------------------------------------------

Ако по някаква причина не можете да предоставите "BARSY_REQUEST_ID", изпратете **всички** изброени по-долу данни:

1. **Хост** — адресът на сървъра, към който изпращате заявките (напр. "https://xyz.barsy.bg" или "https://abc.barsy.online")
2. **Потребителско име** (без пароли)
3. **RAW данни на заявката** — пълното тяло (body) на HTTP заявката, изпратена към API входната точка
4. **Приблизителен ден и час** — кога е изпратена заявката (колкото по-точно, толкова по-добре)
5. **Описание на проблема** — какво наблюдавате, какво очаквате и по какво се различават двете

.. note::

   Алтернативният вариант изисква значително повече време за проследяване. Силно препоръчваме да предоставяте BARSY_REQUEST_ID винаги когато е възможно.


Изпращане на запитването
------------------------

Изпратете събраната информация на адрес: **helpme@lukanet.com**

.. attention::

   **Запитвания без посочената по-горе информация няма да бъдат разглеждани.**

   Без конкретни данни не сме в състояние да извършим проверка. Непълни или неструктурирани запитвания ще бъдат върнати с молба за допълване.


Платен съпорт
-------------

При необходимост от **приоритетно разглеждане**, **архитектурна консултация** или **помощ при изграждане на интеграция**, предлагаме платена техническа поддръжка.

Примерни случаи:

-  Консултация за архитектурата и начина на функциониране на Barsy API
-  Помощ при проектиране и изграждане на интеграция с Barsy API
-  Ревю на съществуваща интеграция и препоръки за оптимизация
-  Приоритетна диагностика и отстраняване на проблеми

За изготвяне на индивидуална `оферта </barsy.help/210-dictionary/offer.html>`__, свържете се с нас на **helpme@lukanet.com**, като опишете накратко:

-  Вашата организация и продукт
-  Естеството на интеграцията
-  Обхватът на желаното съдействие
